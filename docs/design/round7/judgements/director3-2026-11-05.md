## Decision: dc-r7-teaching-scripts (reversal of dc-r7-brain-structural-block triggered)

That block's reversal condition was that "a re-run after S1-S5 shows the same defects". It has: enforcement made her more truthful, but it did not make her teach. **Per-turn improvisation by a reply model, with guards catching errors, cannot produce a coherent lesson.**

**New architecture: the teaching is authored as data, verified offline, and the runtime walks it.**

- **T1. Lesson scripts as data**, one per skill: the authored teaching. Learning authors them and Brain owns the schema. Each script holds:
  - a hook with slots for the child's interests;
  - explanation beats, each naming its board;
  - a FULL worked example: givens first, every step, then "toh jawab" and why;
  - 2 or 3 check questions with keys and the misconceptions each one targets;
  - a practice ladder at class level, using the kit's real items;
  - a class-level remediation per misconception (never counting);
  - bridge lines between skills.

  Claude agents author them in-session, a separate Claude solver blind-verifies them, and a schema check validates them. There are no Azure calls; this follows the precedent of the 18 end-of-class items and the relevel.
- **T2. The Director walks the script.** The move is the next beat. The reply model only turns that beat into natural speech, and first addresses what the child just said.
- **T3. A listening contract, enforced in code:**
  - the reply's first clause answers the child's last turn by its type: answer → verdict and reason; question → an answer; request → do it, or park it with a promise; off-topic → acknowledge and park;
  - wrong answers are always corrected;
  - parked promises must be returned to before the wrap.
- **T4. A screen contract.** The reply step receives what is on screen and must refer to it when something is up. The harness passes the board through. Fraction-on-a-line lessons get a number-line board.
- **T5. Latency.** Find and remove the +0.5 s.

**Pilot first:** one topic per class (the same three topics), 4 scenarios each. Then a director4 run on the scripts, judged the same way.

Reversal: if director4 on scripted topics still shows these gaps, the reply layer is the problem; consider the stronger model on script paraphrase only, or a fully code-rendered teaching voice.
