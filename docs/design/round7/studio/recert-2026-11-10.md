# Studio v2 catalogue re-certified on today's harness (C1 Studio, 2026-11-10)

Main's order (int/r6 dbabc5e52): re-certify everything on today's harness and give a before/after table per engine.

- **What was measured.** Every catalogue game and explainer (382 topics, 760 pieces) was rendered in the real Desk tray and
  StudioStage at p360, p412 and l1366. Each piece carried its board twin, as the live conductor gives it. Classes 4-5 were
  judged at the young floor (16 px).
- **How it was run.** `FORGE3_QA_LOCAL=1 node docs/design/round3/forge/audit/harness/matrix.mjs --sources games,explainers`
  wrote the matrix, and `certificatesFromMatrix` (server/forge3/certify.js) turned it into the certificate.
- **The browser crashes.** In the first run the browser crashed on 268 rows ("Target crashed"), and every later job of that
  worker failed with it. The matrix now opens a fresh page and retries once on a crash, and `--only <ids.json>` re-renders
  just the listed rows. The crashed rows were re-rendered and the two runs merged, so all 760 rows have views and 0 have errors.
- **What changed in the certificate.** `server/forge3/certs/catalogue.json` now holds today's game and explainer rows. Its
  board rows are kept from 2026-10-09.
- **Before** is the certificate of 2026-10-09 (forge3-qa@2, the same checks).

How to read the table:
- Each cell is the number of pieces passing at p360/p412/l1366.
- **Strict** means every hard check passes.
- **Served** is what reaches a child (certify.js `servesView`): a class 4-5 view whose only fault is 14-16 px text is
  still served.

**The p360 column is the board twin, not the game.** At 360 px every piece is served as its twin. The twin
(server/stagecraft/builders.js `boardTwinFor`) is the engine's name as a title plus four of the kit's key terms, with no
figure. It counts as passing because it is legible. Two separate judges, on the pilot packets and on the 20-piece sample,
failed it at p360 in every case because it shows no game. See ENGINES-360.md.
