The figures in the packet's table are all correct. It fails because measure counts any other level as "different", and the server often serves the same key twice in a session. A careful child who makes the same typing slip on every level is then named wrong-scale more than 1 time in 10.

**A. The rule.** vertex-off, centre-on-arm (named only once integration 49 maps it) and wrong-scale are named when her first decision shows the act on two of the session's first four levels. In measure, any two levels with different params count. In draw, the asked size must differ. Measure and draw sightings never count together. join-wrong-end is named on its fourth sighting: four different asked sizes, both button orders, all within the first four levels. The code applies exactly this (`chanceRepeat` specs, `repeatMet`, the `n < NAMING_LEVELS` check in `nameOnRepeat`). The gap: in measure, the surface is `JSON.stringify(params)`, so the same key with only a different tilt or resting pose counts as "differs". The ruling asks for numbers or figures that differ, and for wrong-scale the number is the same on both levels.

**B. Arithmetic.** Every figure reproduces, with only rounding differences:
- Blind placements: 8,905; 2,835; 1,227 / 2,453; 390 / 781.
- Drop that misses: worst at r = 30, 1 in 10.8 (with a band of 11 it is 1 in 9.3).
- Typing slips: 155 is 1/14, 110 is 1/16, 140 is 2/18.
- Over-the-line readings: {16, 140, 141, 159, 164, 165, 166}.
- Session figures: 0.0456, 0.0020 (1 in 498 against the packet's 499), 0.0523, 0.0044, 1/16. From-one-level figures: 0.323, 0.072, 0.344, 0.106. 11/32 and 0.106 at six levels also match.

The p = 0.1 for measure comes from readings 86 and 96, which no level shows. The real worst is 1/14, so the bound is conservative.

**D. Assertion.** It does not cover every generated level. It uses 8 seeds and 178 / 179 param sets. The generator also makes keys 60 (both goals), 65 (draw), 160m and 70m, which are not in the set; none of the served levels I sampled were in it. I checked those keys by hand and they are harmless (slip share 0). The session assertion is a formula over independent levels; it never runs served sessions, so repeated keys and next-level focus steering are invisible to it. The join's slip is hard-coded: `"join-wrong-end": { blind: 0.5, slip: 0, drop: 0 }`. A generator change that put key 140 at a tested seed would be caught (`!m140.includes(140)`, `t.typing <= LAW3`). The repeat hole above would not.

**Faults**
1. **Blocks:** measure's second sighting can be the same key, so a consistent habit tied to the key repeats. The fix is to require a different key on both scales (`apart` on the key, as draw does), then re-run.
2. **Blocks:** the assertion covers a seed sample, not every generated level. The session figure is never checked against served sessions.
3. **Should fix:** the join's slip is hard-coded to 0. The packet's "only button beside" contradicts its own side-or-corner rule.
4. **Should fix:** the packet's key lists are wrong (60 and 65 are generated), and focus steering after one sighting is unstated.
5. **Minor:** wrong-scale's p = 0.1 rests on readings no level shows.

**Watch with real children.** Whether a one-off misread of the other ring's number is a common slip: the packet defines it as the mix-up, and two in four levels would name. Touch offsets on the pad and on the protractor drop. Sessions restarting within a day: the count of four levels resets with each new session, and integration 68 says the unit is now the child's day.
